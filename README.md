# Telegram-бот Atkinternal Planning

Бот для работы с модулем Odoo Planning: создание слотов, изменение/удаление (только созданных ботом), отчёт «свободный ресурс».

## Структура папки `telegram-bots-atkinternal/`

```
telegram-bots-atkinternal/
├── __init__.py
├── __main__.py       # Запуск пакета `bot` как модуля: python -m bot
├── main.py           # Точка входа, создание Application, маршрутизация сценариев
├── config.py         # Конфигурация и константы из переменных окружения
├── core/             # Ядро: Odoo‑клиент и состояние диалога
│   ├── odoo_client.py
│   └── states.py
├── keyboards/        # Клавиатуры (главное меню, inline‑кнопки, Назад/Отмена)
│   └── keyboard.py
├── utils/            # Утилиты: даты, тайм‑зоны, конвертация в формат Odoo
│   └── helpers.py
├── handlers/         # Обработчики сценариев
│   ├── access.py     # Проверка доступа по Telegram ID, привязка к пользователю Odoo
│   ├── menu.py       # /start, главное меню, кнопки Назад/Отмена
│   ├── create_slot.py   # Сценарий 1: создание слота планирования
│   ├── edit_slot.py     # Сценарий 2: поиск/изменение/удаление слотов бота
│   └── free_resource.py # Сценарий 3: отчёт «Свободный ресурс»
├── requirements.txt
└── .env.example
```

### Логика по файлам

- **`main.py`**: инициализация `Application`, подключение `OdooClient`, регистрация:
  - **`MessageHandler`** — обрабатывает:
    - команды из главного меню (`➕ Создать слот`, `✏️ Изменить/Удалить слот`, `📋 Свободный ресурс`);
    - ввод текста в активном сценарии (`create_slot`, `edit_slot`);
  - **`CallbackQueryHandler`** — маршрутизирует все inline‑колбэки на нужный сценарий (префиксы `create_*`, `edit_*`).
- **`core/odoo_client.py`**: обёртка над XML‑RPC Odoo:
  - аутентификация бот‑пользователя;
  - чтение пользователей по `x_telegram_user_id`;
  - чтение отделов, сотрудников, ролей, проектов;
  - создание/чтение/изменение/удаление `planning.slot`;
  - поиск ролей по имени и сотрудников с ресурсом для отчёта «Свободный ресурс».
- **`core/states.py`**: in‑memory состояние диалога на чат:
  - текущий сценарий (`Scenario.CREATE_SLOT`, `EDIT_SLOT`, `FREE_RESOURCE`);
  - шаг сценария и временные данные (выбранный отдел, сотрудник, даты, комментарии и т.д.);
  - `odoo_user_id` и тайм‑зона пользователя Odoo для корректных расчётов дат/времени.
- **`handlers/access.py`**:
  - по Telegram‑ID находит пользователя в Odoo;
  - сохраняет ID и тайм‑зону пользователя в состоянии;
  - централизованно отвечает сообщением об отсутствии доступа.
- **`handlers/menu.py`**:
  - обрабатывает `/start`;
  - показывает главное меню с кнопками действий;
  - по кнопкам «Назад»/«Отмена» сбрасывает состояние сценария и возвращает в главное меню.
- **`handlers/create_slot.py`**:
  - пошаговый мастер создания слота:
    - выбор отдела → сотрудника → роли → проекта;
    - ввод даты начала и окончания;
    - ввод комментария (название слота);
  - создаёт `planning.slot` в Odoo с признаком `x_is_telegram_bot=True` и временем 08:00–17:00 в тайм‑зоне пользователя.
- **`handlers/edit_slot.py`**:
  - поиск слотов, созданных ботом (`x_is_telegram_bot=True`), по сотруднику и периоду;
  - выбор конкретного слота;
  - многошаговое редактирование с возможностью:
    - сменить сотрудника (ресурс);
    - изменить роль;
    - изменить проект;
    - изменить дату начала и/или окончания;
    - изменить комментарий;
    - удалить слот;
  - поддерживает произвольное комбинирование изменений и шаг «подтверждения» перед записью в Odoo.
- **`handlers/free_resource.py`**:
  - отчёт по сотрудникам с ресурсом планирования;
  - для каждого показывает, есть ли слот с ролью «Для распределения» и какие интервалы свободны с учётом других слотов.
- **`keyboards/keyboard.py`**:
  - главное меню (reply‑клавиатура);
  - inline‑списки с навигацией и кнопками «Назад»/«Отмена»;
  - служебные функции построения клавиатур.
- **`utils/helpers.py`**:
  - парсинг и форматирование дат в формате `DD.MM.YYYY`;
  - конвертация локальных дат/времени пользователя Odoo в UTC и формат Odoo (`YYYY-MM-DD HH:MM:SS`);
  - расчёт интервалов дня в заданной тайм‑зоне;
  - получение «сегодня/завтра/послезавтра» для отчёта.

## Требования

- Python 3.10+
- Odoo 19 с установленным модулем `atkinternal_planning_telegram` и Planning (Enterprise)
- Токен Telegram-бота (@BotFather)

## Установка

Из **корня репозитория** (папка `atkinternal-telegram-bot`):

```bash
cd ~/projects/atkinternal-telegram-bot
pip3 install -r bot/requirements.txt
```

Либо из папки бота:

```bash
cd ~/projects/atkinternal-telegram-bot/bot
pip3 install -r requirements.txt
```

## Конфигурация

Переменные окружения:

| Переменная | Описание |
|------------|----------|
| `BOT_TOKEN` | Токен бота (обязательно) |
| `ODOO_URL` | URL Odoo (по умолчанию http://localhost:8069) |
| `ODOO_DB` | Имя БД Odoo |
| `ODOO_BOT_LOGIN` | Логин пользователя Odoo, от имени которого бот создаёт/меняет слоты |
| `ODOO_BOT_PASSWORD` | Пароль этого пользователя |
| `BOT_DEBUG` | 1/0 — включить отладочные логи |

Создайте файл `.env` в папке `bot/` (скопируйте `bot/.env.example` и заполните значения):

```bash
cp bot/.env.example bot/.env
# отредактируйте bot/.env: BOT_TOKEN, ODOO_* и т.д.
```

Пример содержимого `bot/.env`:

```
BOT_TOKEN=123456:ABC...
ODOO_URL=http://localhost:8069
ODOO_DB=odoo
ODOO_BOT_LOGIN=bot_user
ODOO_BOT_PASSWORD=secret
```

В Odoo у каждого пользователя, которому разрешён доступ к боту, в настройках (Preferences) должен быть указан **Telegram User ID** (поле «Telegram User ID»).

### 3. Запуск как сервис (systemd)

Создайте unit-файл (например `/etc/systemd/system/telegram-planning-bot.service`):

```ini
[Unit]
Description=Telegram Planning Bot (Atkinternal)
After=network.target

[Service]
Type=simple
User=www-data
Group=www-data
WorkingDirectory=/opt/atkinternal-telegram-bot
EnvironmentFile=/opt/atkinternal-telegram-bot/bot/.env
ExecStart=/opt/atkinternal-telegram-bot/.venv/bin/python -m bot
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

Замените:

- `User`/`Group` на пользователя, под которым должен работать бот (если не `www-data`);
- `WorkingDirectory` и пути в `EnvironmentFile`/`ExecStart` на фактический путь к репозиторию;
- если виртуальное окружение не используется: `ExecStart=/usr/bin/python3 -m bot` и убедитесь, что в `WorkingDirectory` установлены зависимости (`pip install -r bot/requirements.txt` глобально или в venv).

Подключение и запуск:

```bash
sudo systemctl daemon-reload
sudo systemctl enable telegram-planning-bot
sudo systemctl start telegram-planning-bot
sudo systemctl status telegram-planning-bot
```

Логи: `journalctl -u telegram-planning-bot -f`.

### 4. Важно про Odoo на том же сервере

- Бот обращается к Odoo по `ODOO_URL`. Если Odoo слушает только `127.0.0.1:8069`, задайте `ODOO_URL=http://127.0.0.1:8069` — так трафик не выходит наружу.
- Если Odoo за nginx (например по домену `https://odoo.example.com`), для бота обычно удобнее и безопаснее использовать внутренний адрес (`http://127.0.0.1:8069`), чтобы не зависеть от SSL и внешнего имени.
- Убедитесь, что пользователь Odoo с `ODOO_BOT_LOGIN` существует, имеет права на планирование (Planning) и что в Odoo у сотрудников, которым нужен доступ к боту, в настройках указан **Telegram User ID** (поле из модуля `atkinternal_planning_telegram`).

## Сценарии работы бота

### 1. Создать слот

- **Старт**: пользователь нажимает кнопку `➕ Создать слот` в главном меню.
- **Шаги**:
  - выбор **отдела**;
  - выбор **сотрудника** (только с настроенным ресурсом планирования);
  - выбор **роли** (`planning.role`);
  - выбор **проекта** (можно «— Без проекта —»);
  - ввод **даты начала** в формате `DD.MM.YYYY` (время 08:00);
  - ввод **даты окончания** в формате `DD.MM.YYYY` (время 17:00, дата не может быть раньше начала);
  - ввод **комментария** (название слота).
- **Результат**:
  - создаётся `planning.slot` с:
    - `x_is_telegram_bot=True` (слот помечен как созданный ботом);
    - временем 08:00–17:00 в тайм‑зоне пользователя Odoo;
  - бот отправляет подтверждение с ID созданного слота и возвращает в главное меню.

### 2. Изменить / удалить слот

- **Старт**: пользователь нажимает кнопку `✏️ Изменить/Удалить слот`.
- **Поиск слота**:
  - выбор **отдела**;
  - выбор **сотрудника**;
  - ввод **даты начала периода** (`DD.MM.YYYY`);
  - ввод **даты окончания периода** (`DD.MM.YYYY`, не раньше начала);
  - бот ищет слоты с признаком `x_is_telegram_bot=True` по выбранному ресурсу и периоду и показывает список для выбора.
- **Выбор действий над слотом**:
  - пользователь может отметить один или несколько пунктов:
    - сменить **сотрудника** (и ресурс);
    - изменить **роль**;
    - изменить **проект**;
    - изменить **дату начала**;
    - изменить **дату окончания**;
    - изменить **комментарий**;
    - **удалить слот**.
- **Ввод новых значений**:
  - для выбранных пунктов запускается соответствующий под‑мастер:
    - при смене сотрудника — выбор отдела и нового сотрудника;
    - при смене роли/проекта — выбор из списков;
    - при смене дат — ввод новых дат с валидацией порядка;
    - при изменении комментария — ввод нового текста.
- **Подтверждение и применение**:
  - бот показывает финальный шаг с кнопкой «Отправить изменения»;
  - после подтверждения выполняется `write` или `unlink` слота в Odoo, и пользователь возвращается в главное меню.

### 3. Свободный ресурс

- **Старт**: пользователь нажимает кнопку `📋 Свободный ресурс`.
- **Что делает сценарий**:
  - проверяет доступ пользователя к Odoo и читает его тайм‑зону;
  - ищет роль **«Для распределения»** в `planning.role`;
  - получает всех сотрудников с назначенным ресурсом планирования;
  - для каждого сотрудника рассчитывает статус на:
    - **сегодня**;
    - **завтра**;
    - **послезавтра**.
- **Расчёт статуса по дню**:
  - берутся слоты с ролью «Для распределения» как базовая доступность;
  - из них вычитаются все остальные слоты этого ресурса в том же дне;
  - результатом может быть:
    - `нет слота для распределения`;
    - `занят`;
    - `свободен` / `свободен с HH:MM до HH:MM, ...` в тайм‑зоне пользователя.
- **Ответ**:
  - бот формирует текстовый отчёт с группировкой по сотрудникам;
  - при длинном ответе сообщение разбивается на несколько частей.

На всех шагах диалоговых сценариев доступны кнопки **Назад** и **Отмена** (reply‑ и inline‑клавиатуры), которые позволяют вернуться к предыдущему шагу или прервать сценарий и вернуться в главное меню.
